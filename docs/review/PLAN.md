# 要件定義 v3 レビュー作業計画

対象: `docs/claude_code_falco_plugin_requirements_2026-04-26_v3.md`（1378 行）
目的: 5 ラウンドのフルレビューと修正を行い、論理矛盾・抜け漏れ・整合性の崩れを潰し、収束度を計測する。

## 観点（共通）
1. **論理一貫性**: 主張同士が矛盾していないか。
2. **章間整合**: §0 で言及した方針が §3〜§14 で正しく具体化されているか。
3. **抜け漏れ**: 主対象環境/データフロー/失敗パターン/SLO/運用手順/ライセンス/サポート範囲が言及されているか。
4. **用語ブレ**: plugin name (`claude-code` vs `falco-plugin-claude-code`)、event source、フィールド prefix が統一されているか。
5. **誤りの検出**: SDK 型制約、Falco 仕様、Claude Code 仕様、macOS / Linux ビルドの記述が事実か。
6. **包括/網羅性**: ステークホルダー、運用、サポート、E2E、CI/CD、配布、互換性。
7. **PROBLEM_PATTERNS との突合**: P001-P021 の制約が要件書側に反映されているか。
8. **dev-kit との整合**: テンプレート変数・スキル名・Phase 構造が一致しているか。

## 各ラウンドの目標
- **Round 1**: 章ごとに通読し、章単位の論理ミスと用語ブレを潰す（広く浅く）。
- **Round 2**: 章間整合・参照リンク・テーブル整合・前提条件を潰す。
- **Round 3**: 数値・SLO・閾値・タイムアウト・優先度の妥当性。
- **Round 4**: ステークホルダー・運用・配布・サポート・互換性・撤退戦略。
- **Round 5**: 全体通読で残課題確認、最終収束レポート作成。

## 出力
- `docs/review/round{N}.md` … 各ラウンドの所見と修正リスト
- `docs/review/convergence_report.md` … 5 ラウンドの修正件数推移と収束度評価
- GitHub Issue（タイトル: `要件定義 v3 レビュー（5 ラウンド）`）にコメントで進捗

## ルール
- 修正は要件書本体を直接 Edit する。
- 修正前後で意味が変わらないか必ず確認。
- 修正件数を round{N}.md に列挙し、convergence_report.md で集計。
- ラウンド完了ごとに TaskUpdate と Issue コメントを行う。
