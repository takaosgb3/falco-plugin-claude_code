# Rehearsal Round 5: 最終通読・収束評価

## リハーサル想定シナリオ
Round 1-4 完了後の状態を「初見の実装者」として全章通読する。Phase 別では拾えない横断的な抜けを抽出。

## 抽出論点（最終）

### RH5-01: Linux 導入手順が箇条書きになっていない【手順実行可能性】
**詰まる場面**: §22.1 個人 macOS 導入は 0〜4 の番号付き手順だが、§22.2 「チーム導入」は方針のテーブルのみ。Linux production 環境への導入手順（`/usr/share/falco/plugins/` への配置、`falco.service` の確認等）が一切書かれていない。Round 4 で macOS 手順を補強したが、Linux 側が手薄なまま。

**修正対象**: 要件 §22.2 直前に §22.1.1 として **Linux production 導入** の手順を追加。

---

### RH5-02: scaffold 入力ワークシート（§27.3）への詳細タスク側リンクが抜けている【情報十分性】
**詰まる場面**: Round 1 で要件 §27.3 を新設したが、詳細タスク §5.7 T4-4（plugin-scaffold スキル更新）の「コンテキスト復元」表に §27.3 が含まれていない。T4-4 着手者が要件 §10.2 / §27 を参照しても §27.3 ワークシートに気付かない可能性。

**修正対象**: 詳細タスク §5.7 T4-4 のコンテキスト復元表に「本リポ要件 v3 §27.3（scaffold 入力ワークシート）」を追加。

---

### RH5-03: Pコード食い違い別 Issue の起票テンプレートが未提供【情報十分性】
**詰まる場面**: 詳細タスク §3.7 T2-5 完了基準で「整合プラン別 Issue 起票（3 案: 要件 v3 改訂 / dev-kit 番号付け替え / 並行運用）」とあるが、Issue title / body の雛形が無い。T2-5 着手者は Issue を一からゼロ書きする。

**修正対象**: 詳細タスク §3.7 T2-5 末尾に Issue タイトル例と body 雛形を追記。
